Gateway Fastify (Sync + API)

3.1 Processo de Sincronização

🔄
O scheduler roda automaticamente via cron a cada hora (0 * * * *) + sync inicial 15s após boot. Também pode ser disparado manualmente via POST /api/sap/sales-orders/sync.
1
ensureSchema() — Cria/migra tabelas no PostgreSQL (CREATE TABLE IF NOT EXISTS + índices + views)
2
Paginação SAP — Busca pedidos em lotes de 500 via GET /Orders?$top=500&$skip=N
3
upsertOrderHeaders() — Salva cabeçalhos no PostgreSQL via INSERT ... ON CONFLICT (upsert atômico)
4
Loop até 50.000 — Continua até acabar páginas ou atingir o limite
5
Log de sync — Registra resultado na tabela sap_sync_log

3.2 Normalização dos Dados

3.3 Lazy Loading de Linhas

O sync principal salva apenas headers (sem linhas) para ser rápido. As linhas são carregadas sob demanda:

1
Verifica se existem linhas na tabela sap_sales_order_lines para o doc_entry
2
Se sim → retorna do cache local (source: cache)
3
Se não → busca no SAP via GET /Orders({docEntry})
4
Salva as linhas no PostgreSQL para cache futuro
5
Atualiza num_lines e total_quantity no header

PostgreSQL (Queries SQL)

4.1 Schema do Banco

Tabela: sap_sales_orders (Cabeçalho)
CREATE TABLE sap_sales_orders ( doc_entry INTEGER PRIMARY KEY, doc_num INTEGER NOT NULL, doc_date DATE, doc_due_date DATE, card_code TEXT, card_name TEXT, doc_total NUMERIC(18,2) DEFAULT 0, doc_currency TEXT DEFAULT 'BRL', doc_status TEXT, -- O = Aberto, C = Fechado document_status TEXT, sales_person_code INTEGER, cancelled TEXT DEFAULT 'N', -- Y ou N comments TEXT, num_lines INTEGER DEFAULT 0, total_quantity NUMERIC(18,4) DEFAULT 0, raw_json JSONB, created_at TIMESTAMPTZ DEFAULT NOW(), synced_at TIMESTAMPTZ DEFAULT NOW() );
Tabela: sap_sales_order_lines (Linhas)
CREATE TABLE sap_sales_order_lines ( id SERIAL PRIMARY KEY, doc_entry INTEGER NOT NULL REFERENCES sap_sales_orders(doc_entry) ON DELETE CASCADE, line_num INTEGER, item_code TEXT, item_description TEXT, quantity NUMERIC(18,4) DEFAULT 0, unit_price NUMERIC(18,4) DEFAULT 0, line_total NUMERIC(18,2) DEFAULT 0, discount_percent NUMERIC(8,2) DEFAULT 0, warehouse_code TEXT, price NUMERIC(18,4) DEFAULT 0, cfop_code TEXT, weight NUMERIC(18,4) DEFAULT 0, tax_code TEXT, usage_code INTEGER, UNIQUE (doc_entry, line_num) );
Índices
CREATE INDEX idx_so_doc_date ON sap_sales_orders (doc_date DESC); CREATE INDEX idx_so_card_code ON sap_sales_orders (card_code); CREATE INDEX idx_so_doc_status ON sap_sales_orders (doc_status); CREATE INDEX idx_so_synced ON sap_sales_orders (synced_at DESC); CREATE INDEX idx_so_sales_person ON sap_sales_orders (sales_person_code); CREATE INDEX idx_sol_doc_entry ON sap_sales_order_lines (doc_entry); CREATE INDEX idx_sol_item_code ON sap_sales_order_lines (item_code);

Pontos Críticos e Observações

🚨
Notas Fiscais (Comercial/Dados) NÃO são persistidas localmente — são buscadas diretamente do SAP a cada acesso. Isto pode causar lentidão em períodos longos.
💡
Pedidos de Venda usam cache híbrido: headers no PostgreSQL (sync horário), linhas sob demanda (lazy load do SAP com cache no PG).
ItemDetalhe
Filtro de Canceladoscancelled = 'Y' exclui de TODAS as métricas de valor (faturamento, ticket, etc.). Contagem total inclui cancelados.
Conversão de EmbalagemparseItemInfo() extrai CAIXA/FARDO/PALETE do ItemDescription para converter qty em unidades
Fallback de LinhasSe não há linhas no PG, a query usa raw_json->'DocumentLines' (JSONB) como fallback
Estado do ClienteExtraído via regex do Address/Address2: substring('-([A-Z]{2})\s')
Período ComparativoVisão Executiva compara com período anterior de mesma duração (subMonths)
Limite de SyncMax 50.000 pedidos por sync. Cron roda a cada hora.
Vendedor no FrontendspMap (Map<code, name>) resolve sales_person_code para nome do vendedor
